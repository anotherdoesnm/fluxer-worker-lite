# worker-lite

A Go replacement for the Fluxer `worker` service, written against the wire
contract of Fluxer API release `2026.1026.151750` rather than against its source
tree: the same JetStream subjects (`jobs.<task>`), the same envelope
(`{payload, run_at, created_at}`), the same consumers, heartbeats and dead-letter
subject, but **4–10 MiB RSS instead of 185 MiB** — measured, see `bench/`.

It is not a drop-in replacement: it implements 48 of the 78 tasks and ignores 30 on
purpose, with a reason for each. `REPLACING-NODE-WORKER.md` is the operator document —
what is covered, when the gaps matter, how to switch, verify and roll back.

It is not a reimplementation of Fluxer. It is the background-job half: whatever
this worker does not implement is parked in a separate stream instead of being
lost, and `OMISSIONS.md` lists exactly what is missing.

## Layout

| path | what |
|---|---|
| `cmd/worker` | the worker: lanes, task policy, handlers, `/status` |
| `cmd/observer` | read-only peek into the job stream (never acks, never competes) |
| `deploy.sh` | deploy against the running api container, pass it the api identity |
| `docker-compose.worker-lite.yml` | the same service, for a stock compose stack |
| `wl-status.sh` | human summary of `/status` |
| `bench/` | `bench.sh`: node worker vs worker-lite, isolated broker, memory table |
| `REPLACING-NODE-WORKER.md` | operator guide: coverage, switch, verify, upgrade, rollback |
| `OMISSIONS.md` | what is not ported, and what breaks because of it |

## Design rules

- **Park, never drop.** A task with no handler is copied to `JOBS_PARKED` and only
  then acked; the copy happens first so a failed publish leaves the job in the
  queue.
- **Cron ticks are the exception.** A tick is regenerated by the scheduler (which
  is this worker), so a tick for an unimplemented task is acked and counted, not
  parked.
- **Ignore is a decision with a reason.** Features that are off on this instance
  (billing, app-store, operator pass, search indexing, blocklist feeds) are acked
  and dropped, and the reason is a value in `policy.go`, not a comment.
- **A dead worker must look dead.** `restart: no` on purpose.
- **The spec is generated, not typed.** `spec.go` was parsed out of the api
  image's `dist`; `version.go` records which release, and compares it with the
  digest and build of the api container it is deployed next to.

## Build and deploy

```
tar -czf - . | ssh <build-host> 'tar -C /srv/ci/worker-lite -xzf -'
ssh <build-host> 'cd /srv/ci/worker-lite && podman build -t fluxer-worker-lite:dev .'
ssh <build-host> 'podman save fluxer-worker-lite:dev' | gzip -1 | ssh <fluxer-host> 'docker load'
ssh <fluxer-host> 'docker tag localhost/fluxer-worker-lite:dev fluxer-worker-lite:dev && cd /root/wl-src && sh deploy.sh'
```

Build on a machine with more than 1 GiB: a Go build inside the Fluxer container
was killed by the kernel.

`deploy.sh` reads `BUILD_VERSION` and the image digest off the live `fluxer-api-1`
container, so the worker always knows which API it serves, and prints either
`api matches the spec` or a warning naming both releases.

## Status

`GET :9099/status` (loopback) returns the counters, lane sizes, parked depth and
per-task numbers: `handled`, `parked`, `cron_skipped`, `ignored`, `failed`,
`last_error`. `cron_skipped` is how a task that never needs a handler looks;
`parked` is how a task that matters looks.
